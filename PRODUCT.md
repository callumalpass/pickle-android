# Product

## Register

product

## Users

Pickle is for people who use coding agents and local automations and need to
answer durable requests from a phone. They may glance at a request between
other activities, but they still need enough context to make a deliberate
decision.

## Product Purpose

Pickle is the human checkpoint in an mdbase-backed automation system. Agents
create typed Markdown requests, the app presents the requested response shape,
and a human response becomes a linked Markdown record that later automation
can consume.

Success means pending decisions scan quickly, structured responses are easy to
complete, and the collection remains the sole source of truth. Connecting a
collection and enabling notifications should feel like one coherent mdbase
workflow, not network administration.

## Brand Personality

Quiet, precise, grounded, and trustworthy. Pickle feels like a small operations
desk in the same product family as TaskNotes mobile. It is direct without being
severe and capable without looking like infrastructure software.

## Anti-references

Avoid enterprise workflow suites, chat timelines, task-manager gamification,
dashboard cards, black primary buttons, gradients, mascot energy, raw JSON as
the ordinary response UI, and technical server configuration.

## Design Principles

1. Open into pending decisions.
2. Lead with the requested action, then the context needed to answer it.
3. Render response schemas as familiar controls.
4. Keep lifecycle derived from linked mdbase responses.
5. Treat notifications as wake-up hints, then read current state.
6. Make disconnected state honest because there is no offline replica.

## Accessibility & Inclusion

Target WCAG 2.2 AA and Android accessibility conventions. Controls need
accessible names, 44-point touch targets, visible focus, dynamic-text-friendly
layouts, non-colour state indicators, reduced-motion support, and predictable
screen-reader order. Support system, light, and dark appearance settings.
